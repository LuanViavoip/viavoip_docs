Guia de uso

Os endereços, ramais e identificadores dos exemplos são ilustrativos. Os exemplos não foram compilados: as units de apoio necessárias não estavam disponíveis.

Instalação na IDE

  1. Instale o Overbyte ICS no Delphi (a base usa OverbyteIcsWSocket e OverbyteIcsWndControl).
  2. Tenha no library path as units VVHeader, VVHeadType, VVLib, VVProtocol, VVChannelClient e VVCCTIMID_ConnectWare, além dos arquivos .res de cada componente.
  3. Adicione as quatro units a um pacote de design e instale-o. Cada unit tem seu procedimento Register.
  4. Os componentes aparecem nas paletas ViaVOIP Clients (TVVClient, TVVCTIClient, TVVSIPClient) e ViaVOIP Tools (TVVRoutingClient).

Roteiro mínimo

  1. Informe SHost e, se o servidor não usar a porta padrão, SPort/DPort.
  2. Escolha o modo: assíncrono (padrão) ou síncrono.
  3. Ligue os eventos que interessam — no mínimo OnDebugInfo durante o desenvolvimento.
  4. Chame Start.
  5. Envie comandos depois de OnSocketConnect (ou, em modo síncrono, logo após Start devolver True com Active = True).
  6. Chame Stop ao encerrar. Destruir o componente também fecha as conexões.

Escolhendo o modo

UseQuando
AssíncronoAplicações orientadas a eventos (barras de agente, monitores), em que várias requisições podem estar pendentes e a resposta é tratada em OnServerResponse.
SíncronoFluxos sequenciais (URA, scripts de atendimento) em que cada passo depende do resultado do anterior. Obrigatório, na prática, para TVVSIPClient.

Ativando o modo síncrono

// Aplicação VCL
VVClient1.SetSysApplication(Application);
VVClient1.SyncMode := True;

// Serviço Windows (dentro do TService)
VVClient1.SetSysServiceThread(ServiceThread);
VVClient1.SyncMode := True;

A ordem importa. SyncMode := True é silenciosamente ignorado se nenhuma das duas chamadas tiver sido feita antes — inclusive quando o valor vem do .dfm, que é carregado antes do seu código. Defina SyncMode em código e confira o valor da propriedade em seguida.

Enviando comandos genéricos

Com TVVClient puro, os parâmetros são montados à mão, cada um seguido de cSep: 

sParams := sRamal + cSep + sNumero + cSep;

if VVClient1.SendRequest(iCommand, sParams) then
  ShowMessage('Resposta: ' + VVClient1.RespData)
else
  ShowMessage(Format('Falhou (%d / %d)', [VVClient1.Response, VVClient1.RetCode]));

Correlacionando respostas em modo assíncrono

Defina Filler antes de cada comando; o servidor devolve o mesmo texto no parâmetro sFiller de OnServerResponse, junto com o código do comando respondido. 

VVCTIClient1.Filler := 'tela-atendimento';
VVCTIClient1.CallQuery('2001');

procedure TFormMain.VVCTIClient1ServerResponse(Sender: TObject;
  iCommand, iResponse, iRetCode: Integer; const sData, sFiller: String);
begin
  if (iCommand = RQ_CTI_CALLQUERY) and (sFiller = 'tela-atendimento') then
    AtualizarChamadas(sData);
end;

begin

O socket de debug não reconecta sozinho: chame StartDebug de novo depois de uma queda.

Roteiro: barra de agente com CTI

  1. Start e aguarde OnSocketConnect.
  2. UseCTI(tipo, host, porta, adaptador) e aguarde OnLinkUp.
  3. SetDefExt(ramal) e MonitorStart(tipo, ramal).
  4. ACDLogon(agente, ramal), depois ACDAvail(agente).
  5. Trate OnLineEvent para acompanhar as chamadas e guardar o sCallID.
  6. Use os métodos Call… com o ramal e o sCallID.
  7. Em OnLinkDown, desabilite a interface; ao voltar (OnLinkUp), refaça a monitoração com ReMonitor.
  8. No encerramento: ACDLogoff, MonitorStop, Stop.

Roteiro: aplicação de roteamento

  1. Defina AppType e RegID; mantenha AutoRegister = True.
  2. Start. O registro é enviado sozinho ao conectar.
  3. Aguarde OnRegistered antes de chamar qualquer outro método.
  4. AgentLogon / AgentAvail para os agentes; EnqueueCall / DequeueCall para as chamadas.
  5. Trate OnAgentReserved e OnAgentReleased para saber qual agente recebeu a chamada.
  6. Depois de uma queda, o registro é refeito automaticamente — mas os logons de agente precisam ser reenviados pela aplicação em OnRegistered.

Roteiro: atendimento automático com SIP

// Modo síncrono já ativado; canal aberto com OpenChannel.
while not Terminated do
begin
  if not VVSIPClient1.WaitRing(30000) then Continue;
  if VVSIPClient1.CallID = '' then Continue;      // ninguém ligou

  VVSIPClient1.SetFlushOnDTMF(True);              // DTMF interrompe o áudio
  VVSIPClient1.ClearDigits;
  VVSIPClient1.PlayFiles('menu.wav');
  VVSIPClient1.GetDigits(1, 8000, sOpcao);

  if sOpcao = '1' then
    VVSIPClient1.BlindTransfer('2050')
  else
  begin
    VVSIPClient1.PlayFiles('opcao-invalida.wav');
    VVSIPClient1.ClearCall;
  end;
end;

Depois de uma transferência ou de o chamador desligar, chame IsEstablished (ou um novo WaitRing, que já faz isso) para o componente atualizar CallID.

Criando um novo cliente

Para falar com outro servidor da plataforma, derive de TVVClient:

type
  TVVMeuClient = class(TVVClient)
  protected
    procedure ProcessPacket(const Info: TVVSocketInfoRec;
      const sPacket: String); override;
  public
    constructor Create(AOwner: TComponent); override;
    function FazerAlgo(const sAlvo: String): Boolean;
  end;

constructor TVVMeuClient.Create(AOwner: TComponent);
begin
  inherited Create(AOwner);
  SPort := 7090;          // porta padrão do seu servidor
  DPort := SPort + 1;
end;

function TVVMeuClient.FazerAlgo(const sAlvo: String): Boolean;
begin
  Result := SendCommand(RQ_MEU_COMANDO, sAlvo + cSep, Filler);
end;

procedure TVVMeuClient.ProcessPacket(const Info: TVVSocketInfoRec;
  const sPacket: String);

  if GetParamInt(sPacket, 4) = EV_MEU_EVENTO then
    // campos do evento a partir de GetParam(sPacket, 5)
end;
